## 目标结构

1. **契约真源先行**：订单状态、金额与权限规则归领域；跨进程接口由后端 OpenAPI 和
   `ops/contracts` 版本化 JSON Schema 表达；前端类型从 OpenAPI 生成，不手工复制枚举。
   每个契约变更有兼容性说明、生成检查、负向测试和迁移路径。
2. **领域模块化**：Controller/Bot/定时任务只调用应用用例；用例通过端口访问用户财务、
   机构、服务及外部系统。数据库实体不作为跨域写接口。组合根负责注入实现，禁止业务
   代码导入另一域的 `runtime.ts` 或深层 adapter。
3. **UI 与逻辑分离**：页面和组件只表达场景状态、动作及可访问性；API 协议、重试、
   身份失效、金额显示规则进入可测试的 composable/adapter。UI 不决定订单状态跃迁。
4. **显式状态机**：订单、Telegram 入站、发布/恢复各有独立状态机。状态跃迁只由责任域
   执行；异步副作用经持久 outbox/inbox、幂等键和可核验回执，不以 HTTP 200 或容器
   healthy 替代业务完成。
5. **回滚是完整能力**：基线必须同时证明 Web/API、数据库兼容性、唯一 worker、Telegram
   出站/入站、公开路由和回执链；只恢复旧容器 ID 不等于可回滚。

## 推进顺序与停止条件

### I0：冻结当前故障并保全证据

- 不手改 `deploy-state.json`、资源 pending、租约、回执或旧容器身份；保留失败操作的全链。
- 未完成真实 Telegram 可用性和受控状态迁移前，不安装“能让回执变绿”的降级检查，
  不把 `FAILED` 改成 `IDLE`，不进入生产。
- 每次重试先读 Git SHA、完整测试结果、NAS 状态、容器/网络、端口、数据库、Telegram、
  公共探测和回执；任何不一致保持失败现场。

### I1：业务并发边界（本轮开始）

- `confirm` 事务内锁定订单、校验角色/状态、写回并提交，通知在提交后发出；保留现有
  `PENDING -> RESERVED` 语义，不把 `RESERVED` 偷偷当成待确认。
- 对确认与取消/完成竞态增加 PostgreSQL 并发测试；要求只有一个合法终态、无重复通知。
- 将认证资料更新改为身份字段定向写入，禁止携带余额快照；账户合并另走财务端口及
  同事务的双账户锁和守恒校验。该项未完成前不称资金边界已收口。

### I2：订单产品语义与契约闭环

- 先选定“自动占位”或“商家确认”。若自动占位是目标，应显式描述创建即
  `RESERVED`，确认接口只服务历史 `PENDING` 并有废弃计划；若需商家确认，必须
  设计 `PENDING` 占位/超时/冻结信用/拒单的原子策略，不能只改一个默认状态。
- 同步后端状态规则、OpenAPI、前端可用动作、Telegram 文案、迁移和回放测试。
- 验收真实 PostgreSQL 时间段竞争、幂等重试、取消/失约/争议及资金守恒。

### I3：预发布基线与 G4 重建（需单独设计审查）

- 不在现有旧容器上偷加 hosts、代理环境或透明转发。其镜像/配置/容器 ID 是冻结证据，
  偷改会破坏当前恢复契约。
- 设计新的、仅属 `booking-preprod` 的代理感知基线；为保留的 `FAILED` 事故增加**新的**
  受控收束路径和签名回执，明确旧失败、数据库恢复、Telegram abort、候选隔离、
  新基线启动、公开探测及唯一投递者的先后关系。不能把现有
  `FAILED -> FAILED_RECOVERED -> IDLE` 的证明要求删掉或伪造。
- 先写状态机/schema/动作契约和每个崩溃点的恢复测试，再构建签名镜像及受限执行器；
  只在预发布切换，独立读回，随后以新基线作为两次 30 分钟回滚/再推广验收的目标。
- 任何代理不可达、Webhook/轮询并存、双 worker、数据库不兼容、路由漂移或回执链断裂
  都保持失败，不进入 G5。

### I4：边界与持续质量

- 对每个跨域例外建立“来源、目标、用途、替代端口、迁移测试”的清单；一类一类收紧
  dependency-cruiser，禁止新增豁免。
- 将资金并发 E2E、状态机属性测试、Telegram 重放、生成接口一致性和发布故障注入
  纳入分层质量门禁。单测/类型检查是开发门禁，G4/G5 是独立环境门禁。
- 以缺陷率、回滚耗时、未闭合回执、重复投递、金额守恒和契约生成漂移做每轮验收，
  而不是按改动文件数或容器健康数宣布完成。

## 本轮交付边界

只提交可逆、可单测的订单确认并发修正和责任蓝图；不修改生产或 NAS 预发布运行态，
不改变订单创建状态，不重置 G4 故障状态。I3 是目标设计，不是已经授权或通过的发布。
