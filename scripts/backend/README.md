# 后端脚本说明（scripts/backend）

## 分级
- `backup_*` / `db_*` / `migrate-*`：数据库备份与迁移脚本。
- `reset_*` / `wipe_*` / `clear_*`：数据清理脚本，默认视为高风险。
- `check_*` / `inspect_*`：巡检与诊断脚本。
- `test_*`：后端集成与流程验证脚本。
- `restore_*` / `create_*`：恢复与初始化脚本。

## 使用规范
- 所有脚本默认在本地开发环境执行，不直接面向生产。
- 需要写操作的脚本必须先在测试库验证。
- 高风险脚本（reset/wipe/clear）执行前必须确认目标数据库与环境变量。
- 新脚本命名使用 `verb_subject` 风格，并写明副作用。
- 生产运维动作一律放在 `ops/**`，本目录禁止承担发布、回滚、生产备份职责。

## 推荐执行顺序
- 数据检查：`check_*` 或 `inspect_*`
- 业务验证：`test_*`
- 数据处理：`backup_*` -> 迁移/修复 -> 再次检查

## 风险标记
- **High**：`reset_*`、`wipe_*`、`clear_*`
- **Medium**：`migrate-*`、`restore_*`、`create_*`
- **Low**：`check_*`、`inspect_*`、只读 `test_*`

## 维护约束
- 发布前确认脚本不依赖硬编码密钥与本机专属路径。
- 一次性脚本完成任务后应归档到文档，不长期保留在活跃目录。
- 本目录改动必须经过 Trae 助手评审与执行，不允许手工直接改动。
